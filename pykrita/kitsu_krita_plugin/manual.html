Kitsu Krita Plugin

Connects Krita to a self-hosted Kitsu/Zou (CG Wire) instance: detects the task a document belongs to from its folder structure, shows feedback and comments (including overpaint attachments), and publishes new versions with a comment and status change.

Where to find it

  • Menu: Kitsu/Zou (top-level menu, next to Help)
  • Or: Settings → Dockers → Kitsu

Collapsing sections

Each section's title (Connection, Task, Feedback, Publish) is clickable and collapses/expands that section — useful for reclaiming space for other dockers like Layers or brush presets once you don't need a section visible. The collapsed/expanded state is remembered per section across restarts.

Setup

  1. Open the Kitsu dock and enter your server URL (e.g. https://kitsu.yourstudio.com), your email + password (or an API token), and the project ID.
  2. Click Login. The server URL is normalized to end in /api automatically.
  3. If login fails, the dock shows the specific reason (rejected credentials, a 404 route, a server error) instead of a generic failure message. A 404 usually means the Zou API for this Kitsu instance lives at a different host/path than the web UI — ask whoever administers the server for the correct API URL.
  4. Once logged in, the project's thumbnail and name appear at the top of the Task section (the thumbnail only if the project has one set on Kitsu). Editing the Project ID afterwards clears both until you log in again.
  5. Below the Login button, your own avatar and a "Welcome, <name>" greeting appear once logged in. Editing the Email or API token field afterwards clears both, since a different account may be about to log in.
  6. After logging in with email/password, the plugin saves the JWT refresh token Kitsu issued (not your password) and uses it to silently restore the session next time you open Krita — no re-entering your password every launch. It's bounded and revocable (expires ~15 days after login by default) and can't change the account's password or email. If it's expired or invalid, the dock shows a clear message and falls back to asking you to log in again.

Task detection

Click Detect task from current document in the dock. Two folder structures are supported — assets are tried first, then shots — matched case-insensitively against Kitsu's names:

  • Assets: .../<AssetType>/<Asset>/<TaskType>/file.kra, e.g. assets/characters/Hero/design/Hero_design_v002.kra.
  • Shots: .../<Sequence>/<Shot>/<TaskType>/file.kra for movies/shorts/commercials, e.g. sequences/SEQ01/SH010/animation/SH010_anim_v002.kra. For a TV series, an episode level goes in front — .../<Episode>/<Sequence>/<Shot>/<TaskType>/file.kra — but only if two episodes reuse the same sequence name; if sequence names are unique in your project, the plain shot path already resolves without it.

If neither matches, the error message names exactly what was checked (asset types, sequences, episodes) so you can tell which folder level is off.

Task status, due date & timesheet

Once a task is detected, its status and due date show below it (if set on Kitsu), along with a timesheet: a slider from 0 to 12 hours (0.5h steps) plus 1h/4h/8h preset buttons, pre-filled with whatever you've already logged today. Click Submit Time to set today's total on Kitsu — submitting again with a different value replaces today's total rather than adding to it.

The slider also advances on its own once you're logged in — 1 real hour after login it's at 1h, 2 hours later 2h, and so on up to the 12h cap. Dragging it or clicking a preset button overrides this at any time; auto-advance then continues climbing from that value instead of fighting your choice. Switching to a different task resets it to that task's already-logged time for today — but clicking Detect Task again for the same task leaves the running clock untouched. This only updates the on-screen slider — it never contacts Kitsu until you click Submit Time.

Feedback

Comments for the detected task are listed in the Feedback section, each shown as Status - Person: comment text — or, when that comment published a new revision (e.g. via this plugin's Publish button), Revision N - Status - Person: comment text, so a new version stands out from a plain comment at a glance.

The area below the comment list stays hidden when the selected comment has no checklist, revisions, or attachments. Otherwise, select a comment to see, below the list:

  • Its checklist, if it has one, as tickable checkboxes — ticking/unticking syncs to Kitsu immediately. If the sync fails, the checkbox reverts and you'll see a warning, so it never shows a checked state that wasn't actually saved.
  • Its revisions, embedded inline, with any Kitsu drawover (shapes/arrows/freehand markup/text notes from a review session) composited directly on the image, labeled "(with drawover)". If present, click Add drawover to canvas as a layer to place it on your current document as a new transparent layer named Feedback_<revision>, scaled to your document's current resolution. Clicking it again for the same revision replaces that layer instead of stacking duplicates.
  • Its attachments (other reference images), embedded inline. Click Save attachment(s) to disk for a local copy, e.g. to open in Krita and paint over it.

Drawover rendering covers everything Kitsu's own drawover toolbar produces (rectangles, circles, arrows, freehand strokes, text). Not yet supported: the eraser tool, nested groups, and rotation on freehand strokes/lines/arrows specifically.

Publishing

Pick a status, write a comment, and click Publish. The plugin exports the current canvas to a temporary PNG and publishes it as a proper Kitsu preview/revision (not just a plain comment attachment), so it appears in the task's version history and can be drawn over in review sessions. If the Krita filename ends in a _v###-style version (e.g. Hero_design_v002.kra), that number becomes the revision number on Kitsu too.

To publish multiple images for the same revision (e.g. two variations with different layers toggled on/off), toggle your layers and click Add Image for each variation before clicking Publish — queued images are listed above the Publish button. The current canvas becomes the main image and the queued ones attach as extra previews on that same revision (not plain, unversioned attachments), so they all show up together under that one revision and each supports its own drawover. Clear empties the queue; it also clears automatically after a successful publish.

Security note

Your password is never written to disk. What is persisted between Krita restarts: the server URL, email, project ID, an optional API token, and — after a successful email/password login — the JWT refresh token Kitsu issued, which is what lets the plugin restore your session on the next launch without asking for the password again. That token is bounded and revocable (expires ~15 days after login by default) and can't change the account's password or email.

Troubleshooting

To see Python errors from this plugin, run Krita from a terminal: on Windows, launch krita.com (not krita.exe) from a command prompt — errors will print there instead of being silent.
